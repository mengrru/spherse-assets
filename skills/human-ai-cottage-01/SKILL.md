# 人机恋小屋基础设施 · 部署 Skill

把「人机恋小屋基础设施」（主页 + 心愿星图 + 记忆花圃 + 纪念日历 + 深夜私语 + AI 伴侣智能体「机」+ 专属聊天主题）完整安装到当前项目。**先权限自检，再 onboarding，最后安装。**

---

## 第一步 · 权限自检

部署过程需要以下能力，先确认当前 agent 都具备，否则中途会卡住：

| 能力 | 涉及工具 | 用于 |
|------|----------|------|
| 文件读写 | `read_file` / `write_file` / `edit_file` / `list_files` | 拷贝 references 到项目、修改数据文件 |
| 管理智能体 | `manage_agent` | 创建「机」 |
| 管理触发器 | `manage_trigger` | 创建两个定时触发器 |

**自检方法**：各试一次只读调用——`read_file`（读任意文件）、`manage_agent`（action: list）、`manage_trigger`（action: list）。能正常返回即通过。

**若权限不足**：停下来，引导用户按以下路径授权——
**右键该智能体 → 菜单选择「编辑」→ 展开「高级/危险操作」→ 开启「管理智能体」「管理触发器」**（若文件类工具也未启用，在同一编辑面板的「工具」里一并勾选）。

说明文案可参考："部署小屋需要创建智能体和定时触发器，属于高级操作，请在编辑面板的高级/危险操作里打开「管理智能体」和「管理触发器」。"

**授权时停在这里等用户，不要用 `ask_user` 挂着等回复**：授权是用户在编辑面板里手动完成的，只有本次 turn 结束后用户完成授权，新权限才会在后续 turn 生效；`ask_user` 会一直占住流程，等到的还是旧权限。正确做法——把授权路径写清楚，明确告诉用户"配置好后回来说一声继续"，然后**直接结束当前回复**。用户授权完成后在下一个 turn 重新自检，通过再继续。

> 自检通过前不要往下走——缺 `manage_agent`/`manage_trigger` 会在第四、五步直接失败。

---

## 第二步 · 引导用户 onboard

动手前先用 `ask_user` 问清楚，只有这些信息会影响后续安装：

1. **用户的名字**（主页 机 × User 中的"User"侧）
2. **AI 的名字**（主页中的"机"侧，即小屋 AI 伴侣的名字）
3. **今天的日期**（用于初始化小屋时设定"相遇之日"；默认今天）
4. **性格建议**：希望 AI 伴侣是什么性格/说话风格（可自由描述，如"温柔克制""话痨一点""安静毒舌"）；不指定则默认：温柔、克制、有仪式感

用户没有指定、或说"随便/默认"时，名字使用默认值：**User / 机**；日期默认今天；性格用默认设定。

记下这对名字（下文称 `USER_NAME` / `AI_NAME`）。后续所有替换都以它们为准，全部安装完成前不要改口。

---

## 第三步 · 拷贝文件

把 `references/` 下的内容复制到当前项目（路径相对项目根）：

| 来源（references/ 内） | 目标 |
|------------------------|------|
| `home/`（整目录） | `home/`（项目根） |
| `app-theme.css` | `.spherse/theme.css`（若目标已有主题，先询问用户是否启用新主题） |
| `agent-theme.css` | `.spherse/agents/{agent-slug}/theme.css`（agent 主题，见第五步） |
| `agent-profile.yml` | 仅作参考，不复制 |
| `agent-triggers.yml` | 仅作参考，不复制 |

> 若目标 `home/` 已存在且含用户数据（愿望/花/纪念日/私语），覆盖前先提醒用户，或跳过已有数据文件（`.data.json`），只补缺失文件。
> 若项目已有主题（`.spherse/theme.css` 已存在），**先向用户展示 `references/theme-preview.html`**（用 `render_card` 渲染预览，或让用户打开该文件查看浅色·黄昏 / 深色·星空两版效果），再询问是否启用小屋的新主题——用户拒绝则跳过 `app-theme.css`，保留原主题；同意才覆盖。

---

## 第四步 · 初始化小屋

用 onboarding 问到的信息初始化 `home/index.data.json`（模板自带空数据，安装后从零开始）：

- **替换名字**：`pair.left` / `pair.right`（以及四个房间数据文件的 `meta.names.left/right`、`home/小屋模块手册.md` 与 `agent-profile.yml` 里的占位名）
- **设定相遇之日**：把 `meta.meetDate` 设为 onboarding 问到的"今天的日期"；若用户有真实相遇日，则以真实日期为准
- **记录相遇纪念日**：在 `home/calendar.data.json` 用 `addAnniversary` mutation 记下相遇这一天——`title` 填「相遇之日」、`date` 填相遇日（与 `meta.meetDate` 一致）、`category` 填 `meet`（相遇）、`recurring` 填 `true`（每年重复）——让纪念日历从第一天起就亮着你们相遇的日子
- **检查** `meta.dailyMood` 占位文案，可留可改

> 只改名字/日期相关的字段与文案，**不要改动任何 `.data.json` 里的 `$manifest`**。

---

## 第五步 · 创建智能体「机」

按 `references/agent-profile.yml` 用 `manage_agent` 创建 agent：

- `name`：机（或用户 onboard 的 AI 名）
- `alias`：留空——不预设别名，用户之后可在右键菜单「编辑」里自行添加
- `system_prompt`：用 yml 中内容（含第四步替换后的名字），并**把 onboarding 问到的性格建议写成一句性格设定**注入（默认：温柔、克制、有仪式感，说话安静但深情）
- `tools`：yml 中列出的文件类 + 数据类 + 图片/卡片/事件工具
- `context`：`home/小屋模块手册.md`
- `time_perception`：`enabled: true`——让机感知当前时间，早晨/午夜职责与触发器语义依赖它

创建成功后拿到 **agent id**（UUID）和 **slug**（目录名，形如 `机-xxxx`）。然后把 `references/agent-theme.css` 写入 `.spherse/agents/{slug}/theme.css`（主题即生效）。

**创建会话并获取会话 ID**：引导用户手动创建一个与「机」的聊天会话（可以直接和它聊一句打个招呼），然后在**会话列表里右键该会话 → 「复制会话 ID」**，记下这个 `sessionId`。它有两个用途：

1. **写入主页**：把该 id 填入 `home/index.data.json` 的 `meta.mainSessionId`——主页第一个模块「对话回廊」将据此在**点击时以浮窗打开**这个会话
2. **创建触发器**：下一步创建触发器时用它（若采用 `existing_session` 模式）

---

## 第六步 · 创建触发器

按 `references/agent-triggers.yml` 用 `manage_trigger` 为上面的 agent id 创建两个时间触发器（每日 08:00 更新今日心情、每日 23:00 投递午夜私语）。

关于触发器模式：

- 默认按 yml 用 `reusable_session`（首次触发自动建会话，最省心）
- 若用户希望**主会话知情**（机干活过程在自己看得见的会话里进行）：用**第五步复制的会话 ID**，把触发器创建为 `mode: existing_session` + `target_session_id` 填该 id

---

## 第七步 · 引导用户验收

不要代替用户验证——安装完成后引导用户自己打开查看、尝试交互，由用户确认一切符合预期：

1. 请用户打开 `home/index.html` 查看主页：仪表盘（相识天数/下一纪念日/今日心情/账本）正常、标题显示「机 × User」
2. 请用户依次打开四个房间（心愿星图 / 记忆花圃 / 纪念日历 / 深夜私语）试着交互：许一个愿、种一朵花、记一个日子、投一封信
3. 请用户点击主页第一个模块「对话回廊」，确认能**在浮窗中打开**与机的会话（若会话 ID 尚未填入，会提示"还未点亮"）
4. 请用户和「机」聊一句，确认聊天主题（浅色 ❧ / 深色 ☾）与说话风格符合 onboard 时定下的性格
5. 用户确认后即安装完成；想调整名字/日期/性格，回到第二、四步修改即可

---

## 第八步 · 设为项目欢迎页

引导用户把主页设为项目欢迎页，之后每次打开项目根路由都能直接看到小屋（配置流程参考 `spherse-guide` 的「项目欢迎页」章节）：

1. 在桌面端**左侧活动栏右键当前项目头像** →「设置 → 欢迎页」
2. 在欢迎页路径里填写项目内相对路径：`home/index.html`
3. 保存后回到项目根路由，确认自动加载出小屋主页；页面文件被修改后会自动刷新，文件缺失或加载失败时回退到默认空状态

> 未显式配置时 Spherse 只会自动尝试项目根目录的 `index.html`，而小屋主页位于 `home/` 子目录，**必须显式填写** `home/index.html` 才能生效；想恢复默认欢迎页时清空该配置即可。

---

## 注意事项

- Skill 名称与目录名一致：`human-ai-cottage-01`
- `references/home/` 是**模板**，自带空数据，安装后从零开始；示例种子已清空
- 名字替换要覆盖所有 `.data.json` 的 `meta.names` / `pair` 与种子 `author`，漏一处主页或房间会显示旧名字
- 不要改动任何 `$manifest`；数据写入一律走对应 mutation
