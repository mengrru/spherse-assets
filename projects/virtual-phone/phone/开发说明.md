# 小手机 · 开发说明

> 给**用户**的短文档：**`自定义指南.md`**（怎么改角色 / 加世界 / 加 App，以及改坏了的排错三步）

给「维护这台手机的人 / Agent」看的文档。角色自己不看这份（他们只读世界包里的规则与自己的人设卡）。

## 三层结构

```
phone/
├── world.data.json          ★ 项目配置：当前在跑哪个世界（就这一个字段）
├── 开发说明.md               这份
├── engine/                  ── 引擎层：与世界观无关，所有世界共用 ──
│   ├── index.html            外壳：机身、锁屏、桌面、路由、红点、iframe 宿主
│   ├── theme/
│   │   ├── shell.css         机身外壳样式（只有外壳引，@import themes+skins）
│   │   ├── base.css          共用组件样式（所有 App 引，@import themes+skins）
│   │   ├── themes.css        4 套配色（管「色」）
│   │   ├── skins.css         3 套设计语言（管「形」）
│   │   └── phone.js          ★ 引擎 JS：世界解析 / 数据路径 / 世界时钟 / 未读 / 消息契约 / 外壳通信
│   └── apps/                 各 App 页面（只画界面、发请求，不认识具体世界）
│       ├── chat/ sms/ bbs/ map/ moments/ wallet/ calendar/ notes/ radio/ album/ friends/ settings/ theme/ blank/
└── worlds/                  ── 世界层：一个世界观一个文件夹 ──
    ├── linjiang/            临江 · 2000（现代都市 · 日常系）
    │   ├── world.data.json  ★ 世界清单：品牌文案 / App 注册表 / 货币 / 系统 Agent 名 / 版块名 / 资产
    │   ├── world.md         世界设定（地名、机构、时代、语言风格）→ 所有 Agent 预加载
    │   ├── assets/map.svg   地图美术
    │   ├── characters/      _通用规则.md（角色契约，世界无关）+ 各角色人设卡
    │   ├── system/          系统 Agent 的自包含规则
    │   └── data/            ★ 全部运行时数据（11 个 .data.json，文件名固定）
    └── hogwarts/            霍格沃茨 · 1993（魔法学校）—— 结构完全同上
phone/_archive/               旧文件备份 + 诊断工具（js-check / api-probe / cal-debug / skin-icon-check…，结果都写进 debug.data.json）
```

**判断一个东西该放哪层**：与「这台手机怎么运作」有关 → `engine/`；与「这个世界是什么样」有关 → `worlds/<id>/`。

## 世界是怎么被解析的

```
phone/config.data.json  →  { "config": { "world": "linjiang" } }   ← 项目级：当前跑哪个世界（只有一个；⚠ 别跟世界包里那份 worlds/<世界>/world.data.json 搞混）
      ↓
phone.worlds/linjiang/world.data.json  →  品牌 / App 注册表 / systems / boards / assets
      ↓
所有数据文件 = phone/worlds/<id>/data/<固定文件名>
```

- `phone.js` 里 `FILES` 是**getter**：`phone.FILES.CHAT` 每次取值都按当前世界解析 → 调用点一行都不用改。
- 世界 id **先同步**从 URL 取（外壳给每个 iframe 都带 `?world=xxx`），再由 `phone/config.data.json` 校正；`fixPath()` 会把可能过期的路径纠回来。
- 外壳启动时先 `await phone.ensureWorld()`，再注册文件订阅、渲染桌面（所以订阅盯的是正确的路径）。

## 导航模型

外壳持有唯一路由，持久化在 localStorage（key `xiaoshouji:route:v2`）+ URL hash：

| 路由 | 载入的页面 |
|---|---|
| `#/lock` `#/home` | 外壳自己的视图 |
| `#/chatlist` / `#/chat/<convId>` | `apps/chat/index.html?world=…&view=list` / `&conv=<id>` |
| `#/sms` / `#/sms/<threadId>` | `apps/sms/index.html?world=…` / `&thread=<id>` |
| `#/bbs` / `#/bbs/<postId>` | `apps/bbs/index.html?world=…` / `&post=<id>` |
| `#/map` | `apps/map/index.html?world=…` |
| `#/calendar` | `apps/calendar/index.html?world=…` |
| `#/notes` | `apps/notes/index.html?world=…` |
| `#/radio` | `apps/radio/index.html?world=…` |
| `#/album` | `apps/album/index.html?world=…` |
| `#/moments` `#/wallet` `#/settings` `#/theme` | 对应 App |
| `#/friend/<charId>` | `apps/friends/index.html?world=…&id=<charId>` |
| `#/app/<key>` | `apps/blank/index.html?world=…&key=&name=&emoji=` |

- App 想跳转 → `phone.navigate("chat/conv-xxx")` → postMessage 给外壳 → 外壳换 iframe 的 src。
- 独立打开某个 App 页面时，`phone.navigate` 退化成改自己的 hash；数据则走 SDK（见下）。

## App 是怎么拿到数据的：运行环境三态

Spherse 的 SDK 会被注入到**嵌套 iframe** 里，但它的请求发往 `window.parent` —— 也就是我们的外壳，
没人应答，10 秒后抛 `spherse:timeout`。**所以「有 SDK」不等于「SDK 能用」**，必须握手才能确定。

| 环境 | 判定 | 数据怎么走 |
|---|---|---|
| 外壳自己 | `window.__PHONE_SHELL__` | 直接调 SDK |
| 独立打开（不在任何 iframe 里） | `parent === window` | 直接调 SDK |
| 嵌在外壳的 iframe 里 | 向父窗口发 `hello`，**400ms 内**收到 `shellHello` → `rpc`；超时则当自己能调 SDK | 把请求 postMessage 给外壳**代办** |

外壳侧的 RPC 分发器（`index.html` 里的 message 监听）目前支持这些请求类型：

```
data.entries / data.mutate / data.set / content.listDir / content.upload / toast
session.ensure / session.notify / agent.session / session.send
reload / navigate / hello
```

- **`content.upload` 是上传文件用的**：`{ data: File|Blob, name?, dirPath? }` → `{ path, bytes, renamed }`。
  `dirPath` 是**项目根相对**路径且**必须已存在**（不自动建目录）；音频白名单 `mp3 wav ogg m4a flac aac opus`；
  同名文件会自动改名（`xxx (1).mp3`）；**别照文档断言哪端能用** —— 文档现在删掉了「仅 desktop」那句、只把 `forbidden` 写成「`.spherse` 子树」，
**这件事已经翻过三次面**（旧文档说网页端不行 → 文档改口说行 → 实测被拒 `forbidden` → 复核又行了）——
所以**结论不是"哪端行"，而是"别把它写死"**：文案只报事实 + 原始错误，行为以实测为准。相册/电台的 `whyFailed()` 会 `console.error` 出原始错误。
**结论**：`forbidden` 是平台一道笼统的回绝，文档对它的解释不完整 —— 提示文案**只报事实 + 原始错误**，
绝不替平台解释原因。

**不能写入时的正规入口：**「从项目里挑」—— `phone.listWorldAssets("image"|"audio")`（只读 `content.listDir`，哪端都能用），
样式在 `theme/picker.css`（相册与电台**共用一份**，base.css 已引入）。图片走 `.pick-grid`（缩略图网格），音频走 `.pick-list`（名字列表）。
> 顺手踩的坑：**别在同一条消息里放多个 `edit_file`** —— 哪怕改的是**不同文件**也可能撞车（报 `old_string not found`）；**一次只发一个编辑**，配对读文件/搜索无所谓。为此白折腾好几轮。
  Blob/File 能通过 `postMessage` 结构化克隆送到外壳，所以这条路是通的 —— 页面侧统一用 `phone.uploadFile()`。

- 外壳订阅**全部**数据文件（`phone.allFiles()`），数据一变就广播 `fileUpdate` 给当前 App；
  App 端统一写 `phone.onFileUpdate([...], fn)`，两种环境下写法一样。
- `settings` 里列世界目录（`content.listDir`）也要走外壳 —— iframe 里没有 SDK。
- **不要在新 App 里直接摸 `window.spherse`**，一律用 `phone.*`。

## 引擎层 `phone.js` 的能力

| 能力 | 说明 |
|---|---|
| `phone.FILES` / `allFiles()` | 数据文件路径（按世界动态解析），App 不要自己写死路径 |
| `phone.world()` / `appMeta(key)` / `systemName()` / `boardName()` / `assetUrl(rel)` | 世界清单与其中的名词、资源路径。`assetUrl` = **世界目录内**的资源（地图 `assets/map.svg`、电台音频 `assets/xxx.mp3`）|
| `phone.worldNow()` / `toWorld` / `fmtAgo` / `worldLine()` / `whereLine()` | 世界时钟与时间、位置 |
| `phone.loadShared()` / `entries` / `mutate` / `dataSet` / `onFileUpdate` / `uploadFile` | 数据读写与**文件上传**（`uploadFile({ data: File, dirPath })`，dirPath 必须已存在）|
| `phone.charById` / `conversations` / `myName` / `activeCharacter` | 公共数据快捷读取。`activeCharacter()` 取**会话最近活跃的那个角色**（不要拿它当"随机挑一个人"用 —— 时间戳最新的人会一直是同一个）|
| `phone.unreadOf` / `markSeen` / `totalUnread` / `totalUnreadSms` | 未读 |
| `phone.notify(char, message)` | 静默把消息交给角色（自动建会话、处理忙碌） |
| `phone.createSystemSession(名字)` / `sendSession()` | 系统 Agent 的会话 |
| `phone.prompt.*` | ★ 消息契约模板，与世界的 `characters/_通用规则.md` 一一对应 |
| `phone.THEMES` / `SKINS` / `themeId` / `skinId` / `themeById` / `skinById` / `setTheme` / `setSkin` / `applyTheme` / `defaultLook` | 外观（配色 × 设计语言）与**当前世界的出厂外观** |
| `phone.currency()` / `pageTitle(key)` | 世界包里的货币（符号/名称/快捷金额）与页面标题 |
| `phone.avatarHtml` / `affinitySegs` / `affectionLevel` / `clampAff` / `money` / `ledDigits` | 头像、好感度段条与档位、金额与计数器格式 |
| `phone.mode()` / `rpc()` / `post()` | 运行环境判定与外壳通信（一般不用手写） |
| `phone.navigate` / `onHost` / `params` / `bindEscape` | 与外壳通信、读 URL 参数 |

**消息契约的两端**：`phone.js` 的 `prompt.*` ↔ 世界包的 `characters/_通用规则.md`。改一端必须改另一端。
**每条消息都带「数据文件：…」一行** —— 所以规则文档里不写路径，换世界不用动文档。

## 系统 Agent

每个世界自带若干系统 Agent，**名字由世界包的 `systems` 决定**（引擎不写死）；
会话 id 存在各自 App 的数据文件里，所以换世界不用清。

| 世界 | Agent | 职责 | 会话存哪 |
|---|---|---|---|
| 临江 | **短信局** | 扮演手机之外的世界：机构号、快递、银行、陌生号码、随机小事件 | `data/sms.data.json` 的 `agent.sessionId` |
| 临江 | **临江论坛** | 扮演论坛上的**一群人**：发帖、回帖、抬杠、跑题 | `data/bbs.data.json` 的 `agent.sessionId` |
| 临江 | **临江电台** | 一座深夜档电台：写节目（`shows`），可以配一首歌 | 只需数据文件，不用会话 id |
| 霍格沃茨 | **猫头鹰信使** | 一切信件与通知（校务 / 预言家日报 / 古灵阁 / 家长 / 陌生人） | 同上 |
| 霍格沃茨 | **休息室** | 留言板上的一群学生 | 同上 |
| 霍格沃茨 | **校园无线** | 半夜偷播的电台（不承认是谁） | 同上 |

要点：系统 Agent 都是**扮演一群人**（不是一个角色），所以规则里要写清"你可以是任何人"；
并且都允许**什么都不做**（约一半概率安静，世界才不像机关在按点运转）。

## 怎么加一个新 App（引擎层）

1. 建 `engine/apps/<名字>/index.html`，引 `../../theme/base.css` 和 `../../theme/phone.js`。
2. 页面上方留 46px 给外壳状态栏（照抄现成页面的 `<header class="app-header">`）。右下角要"＋"就用 base.css 里的 `.fab`（几何与默认色都在里面，换颜色加一条 `.fab.xxx{background:…}` 覆写）。
3. 数据：世界相关的放世界的 `data/`（在 `phone.js` 的 `FILE_NAMES` 加一条），共用状态放 `shared.data.json`。
4. 外壳 `engine/index.html` 的 `frameUrl()` 加分支；App 名称/图标在**世界包**的 `apps` 数组里加一条。
5. 需要角色参与 → `phone.prompt.*` 加模板 + 世界的 `_通用规则.md` 加一节。

## 怎么加一个新世界

1. 复制 `worlds/linjiang/` 为 `worlds/<新 id>/`，把内容换掉：
   - `world.data.json`：改名、换品牌文案、换 App 注册表（哪些 App、叫什么、什么图标）、换 systems / boards、换 currency、换电台台标 `station`（`{ name, freq, note }`）；`brand.defaultTheme` 写这个世界的**出厂外观**（`{ "id": 配色, "skin": 设计语言 }`）
   - `data/radio.data.json`：电台的歌与节目。**歌由用户在页面上传**（相册的图片同理）—— 上传落到 `<世界目录>/assets/`（那个目录必须已存在），`tracks[].src` 记项目根相对路径
   - `world.md`：重写世界设定。**必须保留「数据在哪」那一节并改成新世界的路径** —— 它是数据路径的**唯一出处**，角色规则与触发器都指向它
   - `characters/`：写新的人设卡（`_通用规则.md` 可以沿用，它是世界无关的契约）
   - `system/`：写这个世界的系统 Agent 规则
   - `data/`：换成新世界的种子数据（角色、会话、帖子、地点……）
   - `assets/`：换地图等美术
2. 建对应数量的 Agent（每个角色一个 + 系统 Agent 若干），**context 预加载**：`world.md` + 该角色的规则/人设卡。工具勾 `read_data` `query_data` `mutate_data`（角色再加 `read_file`）。
3. 把 `phone/config.data.json` 的 `world` 改成新 id（或者用 `setWorld` mutation 写）。
4. 配触发器：角色按自己的作息，系统 Agent 按「掷骰子/刷新」的频率。四条惯例：
   - **`message` 里不要写死数据路径** —— 触发器是唯一不会自动带「数据文件：…」行的消息，统一写「路径见 world.md 的「数据在哪」」。这是整个项目里**唯一需要知道世界的地方**，换世界时改 world.md 就够。
   - 模式一律 `reusable_session`（同一个会话，角色才记得住上下文）。
   - 每个触发器都要给出「什么都不做」的选项（回「不发」）—— 世界才不像机关在按点运转。
   - 引规则文档时写清**第几节**（章节号会变，写之前去 `_通用规则.md` 对一眼）。

**引擎一行都不用改。**

## 几个刻意的设计

**余额不单独存**：`wallet.initial` 只是基数，余额 = 基数 + Σ(转入) − Σ(转出且未退回)。转账/退回都只写一笔流水，不可能出现「扣了钱没记账」。

**转账状态由角色改**：转出默认 `pending`，角色自己 `setTransactionStatus` 决定 `accepted` / `returned`（退回时钱自动回到余额）。不表态就一直挂着。

**世界时钟**：`手机时间 = anchorWorld + (现实时间 − anchorReal) × rate` —— **任何时间戳都按这个线性换算**（不分锚点前后：早年那些"现实年份"的种子时间戳往回推，正好落在本世界的年代里，不会串出 2025 这种别的年份）。设置页可改基准与流速（1/12/60/180/1440×）。**没有离线封顶**（曾误记为"离线封顶 10 分钟"，实际代码里没有）：手机关着时世界照样在走，流速调得大的话再打开会跳过很多 —— 这是刻意的取舍。`worldClock` 里的 `now` / `label` 是**给角色看的快照**（触发器让角色 `read_data` 读它），由外壳每小时刷一次（`freshenWorldClock()`）。

**外观 = 配色 × 设计语言**（两个正交维度，任意组合）：

- **配色**（`engine/theme/themes.css`）：管「色」。分两类：
  - **外观层**：`--ink`（描边色）、`--wall-*`（壁纸）、`--page-bg` / `--card-*`（页面与卡片底色）、`--sparkles` / `--scan` / `--grid-op`（细节层）、`--sb-on-light` / `--on-wall`（深色壁纸时要翻成浅色的状态栏与桌面文字）、`--sparkle` / `--sparkle-glow`（星屑）、`--petal`（壁纸光晕），以及两个滤镜 `--icon-filter` / `--btn-filter`。

  - `chunky` 描边贴纸（默认）：16/12/18/54 圆角、无衬线、硬投影
  - `flat` 扁平：14/10/14/44 圆角、无衬线、柔和投影、无描边
  - `tome` 手抄本：10/8/11/34 圆角、**衬线**、暖色柔影、细墨线内框
- **分界规则（别再混）**：**圆角与字体属于「形」**，一律放 skins.css；themes.css 里不准出现 `--radius*` / `--bezel-radius` / `--font`。配色只管颜色（含壁纸、滤镜、语义色、身份色、文字色）。曾经这些住在 themes.css 里，导致「描边贴纸」没有自己的圆角、图标圆角跟着配色跑（千禧铬 18px / 蒸汽紫 22px / 魔典 13px / 纸感 10px）。
- **引样式表**：想用「形」的页面必须把 themes.css **和** skins.css 都引进来（`@import` 要写在所有规则之前）。`base.css` 两个都引；`shell.css` 曾经只引了 themes.css —— 于是**整个机身/锁屏/桌面从来没吃到设计语言**（图标没有描边与硬投影，`--gloss-on` 缺值导致高光在扁平/手抄本下也照显）。新页面套样式时先检查这两行。
- **别重复定义 `--ink`**：`:root` 与 `[data-theme="x"]` 权重相同、`@import` 的内容视为写在最前，所以在 base.css / shell.css 里再写一份 `:root{--ink:…}` 会**盖掉主题的值**。引擎自用的只有 `--mono`，其余一律由主题与设计语言提供。
- 两者都写在 `<html data-theme data-skin>` 上，由 `phone.js` 的 `applyTheme()` 设置；两个文件的变量基本不重叠。删掉某一套之后，数据里残留的旧 id 会自动回落到默认值（`themeById` / `skinById` 有兜底），不用改数据。
- 存储：公共数据的 `theme` 对象里 `{ id, skin }`，两个维度都用 `setTheme`（`set` 会合并字段）。
- 主题商店的预览卡片给预览元素同时加 `data-theme` 与 `data-skin`，所以看到的就是那个组合的真实样子（配色与设计语言各选一个）。

**加一套配色**：`themes.css` 写一段变量覆盖 + `phone.js` 的 `THEMES` 登记一条。
**加一套设计语言**：`skins.css` 写一段变量覆盖 + `phone.js` 的 `SKINS` 登记一条（需要结构性改动时，可以在同一个文件里写 `[data-skin="x"] .card{...}` 这样的规则 —— 它会在 base.css 之后生效）。

**乐观发送**：点发送先画气泡，再落盘；拿到真实 id 后由 `file:update` 无缝接管；失败显示可点的红感叹号，重发用同一幂等键。

**角色是有位置的**：`characters[].placeName` 记"他此刻在哪儿"（名字要跟 `map.data.json` 的 `places[].name` 对得上）。这个字段会**跟着每条消息**进 `statusBlock`（「（你现在在：…）」），所以角色随时知道自己在哪，也能判断"他来了我正好在的地方"。地图页反过来读它：地图下面一条横滑的小纸片列"谁现在在哪"，点一下就跳到那个地点；地点详情里列"现在在这里"的人，没有就是"常在这里"（`places[].characterId`，静态的常驻感）。
**位置由谁来维护**：① 角色自己 —— 《通用规则》第 9 节要求他们换地方时把 `placeName` 和 `doing` 一起改；② **"挪位置"定时器** —— 每个角色 agent 一个（触发器会话不知道"我是谁"，所以让每组 agent 照看自己那几个人），每隔几小时按世界时间挪一两个，规则里写明"不用每个人都改、别顺手改好感度、别借机发消息"。

**一个 Agent 可以演多个角色**（霍格沃茨就是这样：哈利 / 罗恩 / 赫敏共用一个 agent）：`characters[].agentSlug` 允许几个角色填**同一个** agent —— 每个角色有自己的 conversation，而 session 挂在 conversation 上，所以同一个 agent 在不同会话里是**互相隔离的上下文**，不会串角色。要这么做只有三个注意点：

1. **人格卡要合并成一份"卡司文件"**：预加载是 agent 级的，一个 agent 只能预加载一份。卡司文件开头必须写清：**先看消息里的「你的档案 id」再决定这次你是谁，只演那一个**。
2. **触发器必须点名**：触发器消息是静态的、不带档案 id，所以每条触发器的文案里要写死「这次你是 X」+「你的会话是 `conv-x`」（省得它去找自己是哪一个）。
3. 角色的 `personaFile` 字段指向那份卡司文件（数据里留个线索，方便人看）。

**怎么分组**：别把十个人塞进一个 agent —— 预加载是 agent 级的，卡司越厚，每条消息都要把整套卡读一遍，越吵、越容易串味。**按"关系"分组**（霍格沃茨就是这么分的）：最亲近的一档一个 agent（三人组）、同院日常一档一个（纳威/金妮/双胞胎/伍德）、外院另一种关系一档一个（马尔福/张秋/塞德里克）。每组 3～5 张卡比较舒服。

**加人只要三步**：写进那张卡司文件 → 在 `characters` 加一条（`agentSlug` 填那一组已有的 slug）→ 在 `conversations` 加一条（**不填 sessionId**，引擎会按需建会话）。触发器可选（只有"会主动找你"的角色才配）。

## 踩过的坑（别再踩）

- **App 在 iframe 里，够不到外壳的 DOM**：凡是要显示在**外壳**上的东西（主题、壁纸），必须让**外壳自己**在「数据变了」的回调里重算一遍。相册设壁纸就是这么做的 —— App 只写公共数据，外壳 `loadData()` 里跟着调 `applyWallpaper()`，于是不用刷新、不用重启手机就换了。别指望 App 直接改外壳。
- **`op: "set"` 的 mutation，目标 key 必须先在数据里存在**：值得是对象（不能是标量），而且那个 key 不能是全新的 —— 否则调用时报 `manifest entry "xxx" is stale (its path no longer resolves)`。加一个新 key（比如 `wallpaper`）时，先在数据文件里把它写成 `{ "src": "" }` 这样的空壳。
- **删一个变量，要连"对它的赋值"一起删**：严格模式下给未声明的变量赋值会抛 `ReferenceError`，而它是**运行时**才炸的 —— `new Function()` 只查语法，抓不到。表现是"某一段功能整块安静地不工作"（我把 `wallOkSrc` 的声明删了却留着赋值 → `applyWallpaper()` 每次都在第一行死掉 → 壁纸怎么设都不生效，两轮排查才发现）。`js-check.html` 现在会静态扫"裸标识符赋值"，而且**自检器自己也自检**（拿这个真 bug 当样本）。它是**保守策略**：只在"整个文件都没声明过这个名字"时才报 —— 做精确的 JS 解析不值得，误报比漏报更坏（第一版按块收声明 + 把 HTML 字符串里的 `class="…"` 当赋值，误报 476 处；第二版漏了逗号声明，仍报 94 处）。教训：外壳里任何一步都要能被上报 —— 我给它加的那句 `wallReport(...)` 就是这个 bug 自己招出来的。

- **别在渲染函数里给常驻元素 `addEventListener`**（会累积）。绑定写在初始化里、用事件委托。
- **`encodeURIComponent(null)` 会变成字符串 `"null"`**：拼 URL 时参数为空就别拼，解析时把 `"null"`/`"undefined"`/空串归一成 `null`。
- **数据文件清单只能有一处**（`FILE_NAMES` → `allFiles()`）：外壳曾漏订阅 `FILES.SMS`，导致写入后界面不刷新。
- **滑动式弹层必须用 `position:fixed`**：`absolute` + `translateY(118%)` 会撑出可滚动区域，把藏起来的弹层滚出来。
- **别给 `.icon` 加 `overflow:hidden`**（会裁掉未读角标）；角标挂在 `.iconwrap` 上，也因此不会被主题滤镜染色。
- **App 页面是固定视口**：`body{overflow:hidden}`，滚动只在内部容器。
- **外壳给 App 的状态栏文字是白色**（App 标题栏都是深色渐变）。
- **搬家之后，正在运行的旧页面可能往旧路径写文件**（`data.set` 会新建）。搬数据后刷新一次页面，并检查有没有多出来的文件。
- **`op: "set"` 的目标路径必须是对象**，不能用它写标量。曾经把「当前世界」写成 `{"world": {"id": "hogwarts"}}`，导致 `WORLD_ID` 变成 `[object Object]`、桌面 App 全空。要写标量就给它包一层（`config.world`）。
- **数据路径的唯一出处是 `world.md` 的「数据在哪」**。曾经有 **8 处**（苏晚的 3 个触发器、临江论坛的触发器、两个世界的 `_通用规则.md` 第 4 节、`短信局.md`、`临江论坛.md`）写死着搬家前的 `phone/shared.data.json` 与 `phone/phone.data.json` —— 文件早就不在了，于是苏晚读不到 `worldClock`，**时间感一直是瞎的**。凡是提到路径的地方，一律写「见 world.md 的「数据在哪」」。
- **添加/修改内容时，顺手 grep 一遍旧路径**：`grep "phone/shared.data.json"` 与 `grep "phone.data.json"`，应当零命中。
- **想用「形」的页面必须同时引 `themes.css` 和 `skins.css`**（`@import` 写在所有规则之前）。`shell.css` 曾漏引 `skins.css` → 整个桌面/锁屏/机身的设计语言没生效（图标没描边没硬投影）。
- **别在 base.css / shell.css 里重复定义 `:root{--ink:…}`**：`:root` 与 `[data-theme="x"]` 权重相同，而 `@import` 的内容视为写在最前，所以后写的那份会**盖掉主题的值**（魔典的铁胆墨因此长期没生效）。引擎自用的只有 `--mono`。
- **加了新数据文件、或改过世界包之后，要重启手机**（设置 → ★ 系统信息 ★ → 重启手机）。运行中的外壳是**打开时读一遍**数据的，之后新加的 `*.data.json`、新加的 `apps[]` 条目（图标路由）它都不知道 —— 症状是：点新 App 走进占位页，或者页面打开了但"没有数据"。别去怀疑数据文件本身（`read_data` 能读就说明它没问题）。
## 调试与自检（改坏了怎么办）

> 这一节是给**要在本项目上继续自定义的人**看的：改了引擎页面、`phone.js`、数据文件之后出问题，按这里查。
> 原则就一句：**别猜 —— 让事实出来。**（症状极具误导性，而这套东西能让事实自己说话。）

### 一、三步排查法

1. **先看 console 的第一条红字。** 它往往**不是"症状所在"，而是"整份脚本挂掉所在"**。真事：症状是"锁屏不显示时间"，
   实际是 `phone.js` 里注释少了收尾 `*/`，把后面 55 行代码整段吞掉 → `phone` 未定义 → **整个外壳死掉**（时间不跳、点不动）。
   顺着症状找会越找越偏：**先看第一个 ReferenceError / SyntaxError。**
2. **再跑 `_archive/js-check.html`**（改过引擎页面或 `theme/phone.js` 之后必跑）。它把 15 个页面的行内 `<script>` 和整份 `phone.js`
   抠出来查 5 件事，结果写进 `_archive/debug.data.json` 的 `jscheck`：
   - ① 用 `new Function()` 试解析 —— 语法错直接报
   - ② 逐行数单引号，**奇数**的那行就是"引号配错了"（会让**整段脚本一行都不执行**，页面只剩静态骨架，看起来像"没数据"）
   - ③ **裸标识符赋值** —— 严格模式下给未声明的变量赋值是**运行时** `ReferenceError`，`new Function()` 抓不到
   - ④ **块注释里包着 function** —— 注释少了收尾 `*/`，后面的代码被整段吞掉（就是上面那个"锁屏不显示时间"）
   - ⑤ **HTML 结构** —— 面板里挤进太多孩子 = 少了 `</div>`，后面的内容被吞进那个默认隐藏的面板，症状是"某块 UI 凭空不见"
   **新页面要加进它的 `PAGES` 清单**，否则它不查那页；它自己还有内置自检（拿真 bug 当样本，扫不出来就报"自检器失效"）。
3. **数据就是真相。** 功能不对时，先直接打开对应的 `.data.json` 看**实际写进去的是什么**（Agent 用 `read_data`，人用编辑器）。
   相当一部分"功能不对"其实是数据没对上，不是代码错了 —— 先看数据能省掉一半排查。

### 二、看不见的地方，让代码自己上报（★ 最有用的招）

代码跑在**用户浏览器里**，屏幕上的东西我们看不到。所以让它在关键步骤把**事实**写出来：
- `console.error("...", 原始错误)` —— **别把原始错误加工没了**（我吃过亏：把平台的 `forbidden` 翻译成"网页版不行"，
  线索反而被我自己吃掉，只能靠猜）
- 把关键结论写进 `_archive/debug.data.json` 的某个 key（例：壁纸的 `wallurl` 记下"哪条候选路径真的取到了图、这张图平均亮度多少"），
  事后 `read_data` 一读就知道卡在哪 —— **相当于给自己装了个 stdout**（`js-check.html`、`cal-debug.html` 也是这么干的）
- 规矩：**只上报事实，不替平台解释原因** —— 原因会变，事实不会
- **上报 URL 时先擦成项目内路径**：预览地址长这样 —— `.../api/projects/<id>/preview/__auth/<token>/phone/...`，
  其中 `__auth/<token>` 是**访问凭据**，而 `debug.data.json` 会随项目一起分发出去。所以凡是要记
  `location.href` / `document.baseURI` / `assetUrl()` 这类**绝对 URL**，先过一遍 `safePath()`（外壳 `index.html`
  里有一份，几个诊断页各自带一份）——它只留 `/phone/...` 之后的部分，令牌就进不了记录。

### 三、要动引擎 API：`_archive/api-probe.html`

它**真的调用** `phone.*`（`worldId` / `assetUrl` / `listWorldAssets` / `worldNow` …）并打印结果。
**重命名或改返回值之后先跑一遍** —— 这类错同样是运行时才炸，静态检查抓不到（我把引擎内部的 `worldDir()` 写成了对外的 `worldId()`，
就是等用户点了才发现）。新增 API 时，顺手把它加进探针。

### 四、改之前先备份

`_archive/` 就是干这个的：**搬过去，不要删**（旧版本留在那儿，随时能捡回来）。改完在 `CHANGELOG.md` 记一条：改了什么、为什么。

### 五、两个环境坑

- **改过引擎文件 / 数据文件之后要"重启手机"**（设置 → 系统信息 → 重启手机）或硬刷新 —— 手机只在打开时读一遍数据
- **聊天里的卡片预览不可靠**（同一路径会缓存、新页面甚至可能不执行）：看到"没生效"别急着改代码，在真实环境里再看一眼
